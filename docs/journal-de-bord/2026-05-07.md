## §266 — Graphe v18p : tri-cluster sémantique

### Problème avec le méga-cluster prophétique (§264)

Le patch §264 avait créé un méga-cluster prophétique (Isaïe, Jérémie, Ézéchiel…
tous liés entre eux par arêtes directes). Effet : toutes les distances entre textes
prophétiques s'effondrent à ~0.05 (1 ou 2 sauts), même pour des textes sémantiquement
distincts. Le signal topologique est écrasé par la densification.

### Solution : tri-cluster sémantique

**Script** : `nipada_graph_patch_v266_prophetic_tricluster.py`

Au lieu d'un méga-cluster, on crée **3 cliques indépendantes** alignées sur les clusters
de signature V14 :

- **Cluster A** — Corpus hébreu prophétique : Isaïe, Jérémie, Ézéchiel, Daniel, Zacharie, Osée
- **Cluster B** — Corpus eschatologique tardif : Apocalypse, 2 Esdras, Hénoch, Oracles Sibyllins
- **Cluster C** — Prophétisme non-abrahamique : Avesta, Völuspá, Chilam Balam

Les trois clusters sont connectés entre eux par une seule arête `indirect` (poids 1.0)
chacun, via un nœud-hub intermédiaire existant dans le graphe.

**Résultat §266** :
- Graphe v18p : 1781 nœuds, 22956 arêtes
- R² = **0.6248** (1025 paires, z=431.2, p=0.000) ✅
- Amélioration nette vs v16p (R² avant §264 : ~0.58)

**Script revalidation** : `nipada_revalidation_v266.py` (pipeline inline V14 §231+)

## §267 — LOO analysis sur v18p (116 textes)

**Script** : `nipada_loo_v267.py`

Leave-One-Out sur le corpus mergé (v263_clean + v264_prophetic) = 116 textes.
Pour chaque texte, retirer + recalcule R² sur les paires restantes.
ΔR² = R²_without − R²_baseline.

**Résultats notables (outliers positifs, ΔR² > 0.04)** :

| Texte | ΔR² | Note |
|-------|-----|------|
| mandukya_upanishad | +0.044 | Upanishad courte, très spécifique |
| kalpa_sutra | +0.036 | Texte rituel jaïn atypique |
| isa_upanishad | +0.020 | Upanishad moniste extrêmement courte |

**Interprétation** : ces textes *réduisent* R² quand on les inclut — leurs signatures V14
sont en désaccord avec la topologie graphique. Mandukya_upanishad en particulier est très
courte (~12 versets) : sa signature V14 est statistiquement peu fiable.

**Outliers négatifs** (ΔR² < -0.02) : textes dont la retrait dégrade fortement R² —
ce sont les textes « porteurs » du signal. Les upanishads majeures (Brihadaranyaka,
Chandogya) sont dans cette catégorie.

## §268 — Extension corpus : diagnostics

### §268a — Tentative protoatheism v208 → INVALIDE

Tentative d'incorporer les 16 textes protoatheism depuis le corpus `signed_corpus_v208.json`.

**Problème découvert** : calibration ÉQUATION incompatible.
- v208 : `ÉQUATION` = 0.1055 (calibré sur graphe v9, 180 arêtes)
- v263 : `ÉQUATION` = 0.0659 (calibré sur graphe v13/v18p, 22000+ arêtes)

Un changement de graphe change la distribution des distances topologiques → la
calibration des poids V14 change aussi. Les signatures v208 **ne peuvent pas** être
comparées directement aux signatures v263.

**Leçon §268a** : toujours re-signer depuis le texte complet (`nipada_fetch_corpus_v212f.py`)
avec la version courante du lexique. Jamais réutiliser des signatures d'une version antérieure.

### §268b — Domaine islamique (4 textes)

4 textes de la falsafa islamique (ibn_rushd×2, al-ghazali, rumi) — calibration correcte v264.

**Résultat** : R²=0.2623 — H₀ *non* violée (signal positif) mais tous 4 textes sont
des outliers (pente d_lex/d_topo ≈ 0.078 vs ≈ 0.12 dans le corpus principal).

**Découverte** : la falsafa islamique partage un vocabulaire aristotélicien avec les
textes grecs → les distances lexicales V14 sont comprimées (ibn_rushd est "trop proche"
de ses voisins grecs). Signal positif, mais calibration spécifique nécessaire.

**Décision** : ne pas intégrer à ce stade. Nécessite un lot dédié avec un graphe
incorporant les arêtes Aristote→ibn_rushd documentées.

## §269 — Couche phrasème/MWE multilingue

**Script** : `nipada_revalidation_v269.py` (inline V14 enrichi)

Ajout d'une couche de reconnaissance de phrasèmes (Multi-Word Expressions) dans la
fonction `freq_signature` :

- `_norm()` : normalisation Unicode + suppression diacritiques (pour FR multilingue)
- `_tokenize_multi()` : tokenisation aware des phrasèmes 2-3 mots avant tokenisation
  par mot unique
- `ATOM_LEXICON_FRA` : lexique unilingue 14 atomes en français (v212f_fra), utilisé
  quand la langue détectée est `fra`
- `PHRASEME_LEXICON` : 206 phrasèmes totaux :
  - 123 ENG : termes canoniques bouddhistes (dharma, brahman, wu wei…), daoïstes,
    hindous, philosophie grecque (nous, logos, eudaimonia…)
  - 83 FRA : équivalents français + termes propres (être-en-soi, mauvaise foi, etc.)

**Impact attendu** : amélioration de la précision pour les textes avec terminologie
technique dense (surtout bouddhiste et grec). Les phrasèmes permettent d'éviter la
dilution d'un concept en mots individuels non reconnus.

## §271 — Graphe v19 + 29 textes grecs (résultat officiel)

### Graphe v19 : 15 arêtes dirigées inter-traditions

**Script** : `nipada_patch_graph_v19.py`

Le graphe v18p avait un problème avec les textes grecs : connectés aux textes
indiens/chinois par des arêtes NON-DIRIGÉES, les chemins Dijkstra pouvaient
utiliser un pont grec comme raccourci (brahma_sutra→plato_phaedo→mengzi = 0.10).
Cela créait des fausses proximités artificielles.

**Solution** : 15 arêtes **dirigées** Greek→Indian et Greek→Chinese (sens de transmission
historique documenté) ajoutées via `build_adj(edges, directed_edges=True)`. Le graphe
v19 ne ajoute ces arêtes que dans un sens — le sens de l'influence historique.

```
Graphe v19 : 1781 nœuds, 22971 arêtes (v18p + 15 arêtes dirigées)
```
